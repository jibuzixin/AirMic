# AirMic 产品需求（原型实现依据）

> v0.3 · 2026-10-24
> 在 v0.2 基础上补充：**预案系统**、**前台应用识别**、**手动扫描**、**麦克风按钮双快捷键绑定**
> 继承 v0.2 已定决策（见 `DESIGN.md` 与文末"沿用的 v0.2 决策"）

---

## 1. 产品定义

**AirMic = 把手机麦克风变成电脑的麦克风，同时把手机变成电脑的遥控器。**

用户坐在电脑前，手机放在手边。想说话就拿起手机按一下；想让电脑执行某个操作就点手机上的磁贴。

### 两端分工

| | 电脑端 | 手机端 |
|---|---|---|
| 角色 | **服务端** | **客户端 + 主控界面** |
| 形态 | 菜单栏图标（`NSStatusItem` / SwiftUI `MenuBarExtra`） | App |
| 窗口 | 只有一个下拉面板，**无 Dock 图标** | 正常全屏 App |
| 职责 | 接收音频、执行快捷键、识别前台应用、配对管理 | 采集音频、发送快捷键、管理预案 |

**为什么电脑端只做菜单栏**：它是个"后台常驻"角色，不该抢焦点、不该占 Dock、不该在用户没主动查看时占据视觉空间。AirMic 的全部交互重量在手机端。

## 2. 电脑端需求

### 2.1 菜单栏面板

固定宽 **318px**。纵向顺序（不可变）：

```
┌────────────────────────────────┐
│ ● 已连接 · iPhone 15 Pro        │  1. 状态行
│ 当前应用：微信                   │     （含前台应用名）
├────────────────────────────────┤
│ 配对码  4 8 2 9 1 6    [刷新]    │  2. 配对码
├────────────────────────────────┤
│ 音频输出  [BlackHole 2ch ▾]     │  3. 输出设备下拉
├────────────────────────────────┤
│        [  开始收音  ]            │  4. 主按钮（琥珀）
├────────────────────────────────┤
│ ▸ 详细设置                      │  5. 折叠区
├────────────────────────────────┤
│ 退出 AirMic                      │  6. 退出
└────────────────────────────────┘
```

- **状态行**：连接状态点（灰=未连 / 绿=已连）+ 设备名 + **当前前台应用名**
- **配对码**：6 位数字，等宽字体，字间距 0.2em，折叠时隐藏
  - 码旁边是**刷新**按钮（不是复制）—— 配对码是临时的，复制没有意义
  - 点刷新 → 立刻换一个 6 位新码，**旧码立即失效**；旧码在手机端会得到「配对码已过期，在电脑端重新生成一个」
  - 换码时新数字淡入 + 刷新图标转一圈
- **输出设备下拉**：列出系统音频输出设备（BlackHole 在内）
- **主按钮**：开始/停止收音。停止时主按钮是次要样式
- **详细设置（默认折叠）**：
  - 统计：丢包 / 抖动 / 欠载 / 延迟（四个指标）
  - 抖动缓冲设置
  - 1kHz 测试音
- **退出**：普通文字按钮，不做危险色（退出不是破坏性操作）

**常态不显示统计**。这是排查功能，不是日常信息。

### 2.2 前台应用识别

- 持续检测当前**最前端**应用的名称（macOS：`NSWorkspace` 前台应用通知）
- 应用名显示在状态行
- **用途**：手机端据此判断该用哪个预案
- 应用切换时，手机端自动切换预案（见 §4.3）

原型里用一个**模拟前台应用切换器**演示（手点切微信/终端/Notion），真实实现时才接系统 API。

### 2.3 配对与连接

两种配对路径，**都要支持**：

**路径 A — 手机发起，电脑确认**

> ⚠️ **只针对「未配对」的设备。**
> 配对过一次之后，电脑端会记住这台设备；手机端在设备列表里点它**直接连上**，
> 不需要再发配对请求、电脑端也不需要再点一次同意。
> 只有下列情况才走配对流程：
>   - 这台设备电脑端从没配对过
>   - 电脑端**主动删除**了这台设备的配对信息（用户想重新授权）

1. 手机点**未配对**设备 → 发配对请求
2. 电脑端菜单栏图标弹提示（铃铛动效），显示"XXX 请求配对"
3. 用户点"允许" / "拒绝"
4. 允许 → 双方建立长期连接，交换 token，电脑端**记住这台设备**

**路径 B — 输配对码**

1. 电脑端面板显示 6 位配对码
2. 手机端手动输入该码
3. 校验通过 → 建立连接，电脑端同样记住这台设备

**电脑端解绑**

- 电脑端面板有「已配对设备」列表，每台可以删除配对信息
- 删除后如果正连着它，连接立即断开
- 这台手机下次打开必须重新配对

**配对码规则**（沿用 v0.2）：
- 6 位数字
- 一次校验 → 长期记住设备
- **双端都能解绑**；解绑后必须重输配对码
- 配对码有有效期（过期需重新生成）
- 电脑端提供**刷新**入口：换一个新码，旧码立刻作废（用户反馈 v0.6：码旁边不该是复制按钮）

### 2.4 接收与执行

- **音频**：手机持续推流，电脑写入虚拟音频输入设备
- **快捷键信号**：手机发组合键，电脑用 `CGEvent` 模拟按键
- **心跳**：双方维持连接，断了要能恢复

## 3. 手机端需求

### 3.1 路由规则（不可变）

```
未配对  → 永远进「设备页」
已配对  → 每次打开直接进「麦克风页」
```

不做"首页/中间页"。用户要的是**打开就能用**。

### 3.2 设备页

**扫描策略（用户明确要求）**：
- **不持续扫描**。持续扫描费电、费网络。
- 提供**手动刷新**按钮
- 进入页面时扫描一次，之后靠用户手动刷
- 扫描中显示 loader，扫完显示结果

**设备列表项**：设备名 / 机型 / 信号强度（4 格）

**两种配对入口**：
- 点设备 → 发配对请求（走 §2.3 路径 A）
- 「输入配对码」→ 手动输 6 位码（走路径 B）

**空状态**：不能只写"没有找到设备"，要说明"手机和电脑要在同一个 Wi-Fi 下" + 给刷新按钮。

### 3.3 麦克风页（完全不滚动）

```
┌─────────────────────────┐
│ iPhone 15 Pro    ● 已连接│  状态条
│ ● 当前预案 聊天预案 · 微信│  预案条（**常驻**，切换时闪一下琥珀点）
├─────────────────────────┤
│                         │
│      ◜ 环形电平表 ◝     │  300px
│        ( 麦克风 )        │  132px 主按钮
│      点按收音·长按说话    │
│   [按下 ⌘⇧V] [松开 ⌘⏎]  │  麦克风按钮自己的绑定（可点 → 去设置）
│                         │
├─────────────────────────┤
│ ┌────┐┌────┐┌────┐     │
│ │ 🎙 ││ ⏎ ││ 🔍 │     │  3×2 磁贴
│ │语音││发送││搜索│     │  图标/名称/组合键
│ │⌘⇧V││⌘⏎││⌘Space│    │
│ └────┘└────┘└────┘     │
│ ┌────┐┌────┐┌────┐     │
│ │ ▶  ││ ↩  ││ ⧉  │     │
│ │播放││撤销││复制│     │
│ └────┘└────┘└────┘     │
└─────────────────────────┘
```

**麦克风按钮双语义**：
| 操作 | 判定 | 行为 |
|---|---|---|
| 点击 | < 220ms | 切换**常开收音**；再点一次关闭 |
| 长按 | > 220ms | **瞬时说话**；松开立即停止 |

**其他行为**：
- **静默**：长时间不说话自动静默（不再推流）
- **省电**：电脑端当前没有应用在用麦克风时，**不发送音频**
  （判断逻辑：电脑端检测当前前台应用是否在录音状态 —— macOS 可查 `coreaudiod` 的活跃客户端；简化版可用"最近 N 秒无输入则停推"）
- 常开收音时按钮呈琥珀色；瞬时说话时呈红色

**磁贴规则**：
- 只对应**电脑快捷键**
- 三行固定结构：图标 / 名称 / 组合键
- 组合键用等宽字体（`⌘⇧V`）
- **电脑端没绑定的磁贴显示暗态**，点击提示"先在电脑端配置"
- 磁贴固定 3×2，不滚动

### 3.4 预案管理页

手机端可管理预案：
- 列出所有预案：名称 / 绑定应用 / 快捷键数量
- 默认预案有明确标识
- 新建 / 编辑 / 删除
- 选择绑定哪个电脑应用（列表来自电脑端上报的前台应用集合）

**快捷键怎么设置（必须能在原型里看到完整流程）**：

| 入口 | 位置 | 作用 |
|---|---|---|
| 麦克风页的「按下 / 松开」芯片 | 电平表下方两枚小药丸 | 点一下直接打开当前预案的麦克风绑定设置 |
| 预案页 → 点某套预案 | 预案列表项 | 打开这套预案的完整编辑抽屉 |

编辑抽屉里分**两个独立区块**，不能混为一谈（§4.2）：
- **麦克风按钮**：按下时 / 松开时各选一个**磁铁**（点开从磁铁库里挑，或当场新建一个）。
- **独立快捷键磁贴**：每行显示磁铁的图标 + 名字 + 组合键，点键位可以换成别的磁铁；可增删磁贴（0–6 个）。

抽屉底部还有一块**磁铁库**（全局的，折叠收起），可以新建 / 编辑 / 删除磁铁。

两处都必须**当场生效**（不能等保存），否则用户会以为点不动。

**弹层交互要统一**（用户反馈 v0.6）：手机端所有弹层用同一套规则 ——
- 预案编辑抽屉、磁铁选择器、磁铁编辑器 **一律从下往上滑出**（spring，只动 transform）
- 弹层后面都有一层半透明遮罩，**点空白处退出**
- 顶部有拖动条，右上角有关闭按钮 —— 三种关法都要有

**磁铁编辑流程**见 §4.1：选图标 → 起名字 → 用键盘 + 鼠标菜单录快捷键。

## 4. 预案系统（核心差异化功能）

### 4.1 磁铁（Hotkey Magnet）

**磁铁 = 一个可复用的快捷键定义：图标 + 名字 + 一组按键。**

磁铁是**全局**的，不属于某一套预案 —— 预案的磁贴和麦克风按钮的按下/松开
共用同一批磁铁。改一次磁铁，所有引用它的地方一起变。

**创建磁铁的流程（三步，全程可点改）**：

1. **选图标** —— 从内置图标库里挑一个
2. **起名字** —— 比如「语音输入」
3. **录快捷键** —— 用软件内置的**键盘 + 鼠标菜单**，
   依次点出想要的组合键：
   - 修饰键多选（⌃⌥⇧⌘，按 macOS 习惯顺序显示）
   - 键盘主键单选（字母 / 数字 / 功能键 / 编辑键 / 方向键 / 符号）
   - 鼠标键单选（左右中键 / 滚轮上下），跟键盘主键互斥
   - 全程有实时预览（显示成「⌘⇧V」这样）

> 不做"在输入框里手打组合键"那种交互 —— 逐个点才是可靠的。

**磁铁没有配任何键时是暗态**，磁贴显示为未设置，点击提示去配置。

### 4.2 预案是什么

**预案 = 一套完整的快捷键方案。** 包含三部分：

1. **麦克风按钮「按下」时执行的磁铁**（可选）
   - 例：按住说话时，电脑同时触发「语音输入」磁铁（⌘⇧V）
2. **麦克风按钮「松开」时执行的磁铁**（可选）
   - 例：松开时，电脑触发「发送」磁铁（⌘⏎）
3. **独立快捷键磁贴**（0–6 个）
   - 例：全局搜索 ⌘Space、撤销 ⌘Z
   - **这些不与麦克风绑定**，是单独的功能按钮

⚠️ 1 和 2 是**麦克风按钮上绑两个不同的磁铁**；3 是**独立按钮**。UI 上必须区分清楚，不能混为一谈。

> 1 和 2 选的是**磁铁**，不是直接选按键 —— 这样同一个「语音输入」磁铁
> 既能当磁贴用，也能绑给麦克风按钮的按下动作。

### 4.3 预设预案

原型内置 4 套（数据见 `src/lib/airmic-data.ts`）：

| 预案 | 绑定应用 | 麦克风按下 | 麦克风松开 | 说明 |
|---|---|---|---|---|
| 默认预案 | — | ⌘⇧V 语音输入 | ⌘⏎ 发送 | 兜底 |
| 聊天预案 | 微信 | ⌘⇧V | ⌘⏎ | 说话即输入，即说即发 |
| 终端预案 | 终端 | ⌃Space 开始录音 | — | 终端里要的是录音命令 |
| 写作预案 | Notion | ⌘⇧V | — | 写作场景不需要自动发送 |

### 4.4 自动切换规则

```
电脑端检测到前台应用变化
        ↓
查该应用是否绑定了预案
        ↓
  ┌─────┴─────┐
 是            否
  ↓            ↓
切到绑定预案   切到「默认预案」
  ↓            ↓
手机端顶部「当前预案」条更新 + 强调一下
```

**关键设计决策**：
- 切换用**顶部状态条**，**不用弹窗** —— 弹窗会打断正在进行的说话动作
- **当前预案是常驻显示的**，不是临时通知。
  用户需要随时知道"现在用的是哪一套预案"，所以这条不自动消失。
  切换发生时只做一次短暂的强调（琥珀色圆点闪一下），2 秒后回到中性色。
- 切换要**可见但不打扰**
- 切换本身不能中断正在进行的收音
- 没绑定的应用走默认预案时，状态条显示「XX · 默认预案」，
  表达的是"当前在用哪套"，不是"出错了" —— 不弹任何错误提示

### 4.5 前提条件

**前提是用户配置好了绑定。** 没配的应用一律走默认预案 —— 这是兜底，不是错误，不该弹任何提示。

## 5. 原型要表达什么

原型不是每个像素都要还原，**它要证明三件事**：

1. **手机端一屏放下、零思考成本** —— 打开就能说话
2. **麦克风按钮的双语义直觉上成立** —— 用户不用读说明就知道"点=常开、按=瞬时"
3. **预案自动切换是看得见的** —— 切前台应用 → 顶部条提示 → 磁贴内容整体换了

演示脚本建议：
1. 手机端已配对 → 直接进麦克风页
2. 点麦克风 → 琥珀色常开 → 电平表跳动 → 再点关闭
3. 长按麦克风 → 红色瞬时说话 → 松开即停
4. 切电脑端"前台应用"到微信 → 手机端顶部出现"已切换到「聊天预案」" → 磁贴全变
5. 切到 Safari（没绑预案）→ 切回"默认预案"
6. 断开设备 → 手机端退回设备页 → 手动刷新扫描 → 点设备发配对请求
7. 电脑端弹配对请求 → 同意 → 重新连上

## 6. 沿用的 v0.2 决策（已定，勿推翻）

**电脑端**
- 面板外观**完全跟随 macOS**：vibrancy 毛玻璃 + 系统蓝 + 原生控件，**不自绘配色**
- 面板只有：状态 → 配对码 → 音频输出下拉 → 启动/停止 → 折叠的详细设置 → 退出。**没有截图等杂项**
- 统计（丢包/抖动/欠载/延迟）+ 抖动缓冲 + 1kHz 测试音 **默认折叠**
- 面板宽 318pt
- **电脑端不显示手机的自定义按钮**（保持极简）—— 注意：这一条指**菜单栏面板**不显示；手机端的磁贴是手机端的事

**手机端**
- 没配对 → 永远进设备页；已配对 → 每次打开直接进麦克风页
- 麦克风页**完全不滚动**；设备页/设置页才可滚
- **只有一颗麦克风按钮，双语义**（点按=常开，按住=瞬时说话，<220ms 判为点击）
- 删掉截图/复制/静音等快捷 chip；遥控磁贴**只对应电脑热键**（图标+名称+组合键三行）
- 配色：深色 + 单一强调色**琥珀 #FFB020**，语义色连接绿 **#35C98A** / 收音红 **#FF5A5A**
- 电平表 48 柱径向，环 300pt
- ⚠️ `.polar-bars` 必须 `pointer-events:none`（旋转方块会溢出挡住下方按钮）

**低占用目标（写进设计约束）**
- 空闲 CPU < 0.3%，常驻内存 < 40MB，收音时 CPU < 8%
- 手机端不常驻录音，按需拉起；协议单连接、少字段
