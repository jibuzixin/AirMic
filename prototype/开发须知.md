## 2. 最终产品形态与架构（**已经定好，不要自己发明**）

```
┌─ macOS 电脑端 ────────────────────────────────────────┐
│                                                        │
│  ① 菜单栏 App（不占 Dock）                              │
│     Tauri 2 + React（复用原型 src/components/mac/）     │
│     └─ native 能力走 Swift sidecar（IPC 调）           │
│                                                        │
│  ② 虚拟音频输入设备  ← ★ 必须 native，Web/Tauri 都做不了 │
│     Swift/ObjC/C++，AudioUnit 或 AudioDriverKit         │
│     手机推的 PCM 写进来，系统里能当成一个麦克风选中      │
│                                                        │
│  ③ 前台应用监听 → 预案自动切换                          │
│     Swift: NSWorkspace / AXObserver                     │
│                                                        │
│  ④ 快捷键执行 → CGEvent 模拟按键                        │
│     Swift sidecar（注意：CGEvent 需要辅助功能权限）      │
│                                                        │
│  ⑤ 通信服务（与手机端）                                 │
└────────────────────────────────────────────────────────┘
                          ↕ 局域网（mDNS 发现 + 推流）
┌─ 手机端（iOS / Android）───────────────────────────────┐
│  麦克风采集 → 编码（Opus）→ 推流                        │
│  遥控 UI（复用原型 src/components/phone/）              │
└────────────────────────────────────────────────────────┘
```

**必须记住的三条架构结论：**

1. **虚拟音频输入设备必须用 Swift/ObjC/C++ 写。** Web Audio 和 Tauri 都做不到
   「在系统里注册一个麦克风设备」。这是整个项目最硬的约束，别浪费时间试 Web 方案。
2. **Tauri 2 负责窗口/托盘/打包，native 能力一律走 Swift sidecar。**
   UI 用 React/Tauri 没问题，音频和系统集成单独走 Swift。
3. **目标形态**：Tauri 2 → macOS `.app` + Android `.apk`。

## 3. 原型里哪些是「假的」—— 接手第一件事就是换掉它们

原型为了能演示，所有外部世界都用假数据顶上了。下面这张表是**你的活儿清单**：

| 原型里的假东西 | 位置 | 真实实现 |
|---|---|---|
| 4 台写死的设备 | `src/lib/airmic-data.ts` `SCANNABLE_DEVICES` | 局域网发现（mDNS/Bonjour，service type `_airmic._tcp`） |
| 6 个写死的前台应用 | `airmic-data.ts` `FOREGROUND_APPS` | macOS `NSWorkspace.frontmostApplication` / `AXObserver` |
| 写死的输出设备 | `airmic-store.tsx` `OUTPUT_DEVICES` | CoreAudio `kAudioHardwarePropertyDevices` |
| 假统计数字 | `airmic-data.ts` `INITIAL_STATS` | 真实音频管线统计。**拿不到真实数据前一律显示 `[--]`** |
| `setTimeout(900)` 当扫描 | `airmic-store.tsx` `startScan` | 真实扫描 + 设备列表更新 |
| `setForegroundApp` 手动调用 | `airmic-store.tsx` | 系统事件驱动 |
| 配对码是模块常量 | `airmic-store.tsx` `DEMO_PAIR_CODE` | 真实配对协议：一次性码 + 长期 token |
| `refreshPairCode` 随机数 | `airmic-store.tsx` `nextPairCode` | 服务端生成 + 有效期 |
| 全部状态是 `useState` | `airmic-store.tsx` | 持久化（配置用 Tauri store / SQLite）+ 跨端 IPC 同步 |
| 中间那栏「演示控制台」 | `src/App.tsx` | **正式版删掉**，它是演示脚手架不是产品界面 |
| 麦克风页的震动提醒 | `src/components/phone/MicPage.tsx` | 保留，但触发条件要读**真实的**电脑端收音状态 |
| 磁铁 / 预案 / 设备列表 | `airmic-data.ts` | 真实存储 + 同步 |

### 3.1 关键设计建议：保留 store 的**接口形状**

`src/lib/airmic-store.tsx` 里的 `AirmicStore` 接口定义了 UI 需要的全部状态和动作。
**真实实现时，请保持这个接口的形状不变**，只把 `useState` 换成「订阅 IPC / 本地存储」的
真实实现。这样 **UI 组件一行都不用改**，只需要换掉 store 的内部。

换句话说：
- `AirmicStore` 的**字段和方法名** → 保持
- `AirmicStore` 的**数据来源** → 从内存 state 换成真实通道
- 新增真实能力时，往接口上加方法，**不要在组件里直接调 native**

## 4. 建议的阶段计划（每阶段都要能验收）

按这个顺序做，每一步都能独立跑起来看到效果。**不要一上来就写音频内核。**

### Phase 1 — 通信骨架（两端能通）
- 手机端和电脑端建立连接（局域网，UDP/TCP 自定）
- 打通：心跳、设备列表、状态上报
- **验收**：电脑端能看到手机在线；手机端能看到电脑在线

### Phase 2 — 音频管线（手机上能听到电脑）
- 手机麦克风采集 → 编码（Opus）→ 推流；电脑端解码
- 先用**文件或扬声器**验证，不接虚拟设备
- **验收**：电脑端能播放手机端的声音，延迟可测

### Phase 3 — 虚拟音频输入设备（系统里能选到）
- Swift 写虚拟输入设备，把 Phase 2 的 PCM 写进去
- **验收**：系统「声音」设置里能看到并选中 AirMic 输入设备，任意录音 App 能录到手机的声音

### Phase 4 — 快捷键执行
- 手机端发快捷键 → 电脑端 `CGEvent` 模拟按键
- 复用 `src/lib/hotkey.ts` 的 `magnetCombo()`（下发串已经算好了）
- **验收**：手机点磁贴，电脑上真的按下 ⌘⇧V

### Phase 5 — 前台应用监听 + 预案自动切换
- Swift 监听前台应用 → 查绑定预案 → 切换 → 通知手机端
- **验收**：切到微信，手机端顶部预案条自动变成聊天预案

### Phase 6 — 配对与持久化
- 一次性配对码 + 长期 token；两端记住设备
- 已配对设备点一下直连；电脑端删配对信息后手机端必须重新配对
- 磁铁/预案/设备列表持久化
- **验收**：重启两端，配置还在；删配对后流程正确

### Phase 7 — 打包发布
- Tauri 2 打包 macOS `.app`（菜单栏应用、不占 Dock）
- Android 端（`.apk`）—— 时间不够可以放到最后
- **验收**：双击 `.app` 出现在菜单栏，能跑通完整链路

## 5. 硬约束（19 条，来自 `HANDOFF.md` §9 —— 违反即 bug）

### 架构层
1. **虚拟音频输入设备最终必须 Swift/ObjC/C++**。别误以为整条链路能用 Web 搞定。
2. 目标形态：Tauri 2 → macOS `.app` + Android `.apk`。

### 设计层
3. **电平表两个 SVG 都要 `pointer-events:none`**。
4. **AI 味 UI 是 bug** → 见 `DESIGN.md` §10 禁止清单。**假数据指标绝对不能出现**（`99.99%` 这种）。
5. **动效只用 spring**，只用 `@/lib/motion` 的 token，不手写 stiffness/damping。
6. **长按 vs 点击阈值 220ms**，不要改。
7. **手机端麦克风页完全不滚动**，一屏放下；设备页/设置页才可滚。
8. **纯黑 `#000000` 禁止**，最深是 `#0B0B0D`。
9. **琥珀色是稀缺资源**，一个视图最多一处主操作。

### 产品层
10. **「麦克风按钮按下/松开绑定快捷键」和「独立快捷键磁贴」是两件事**，UI 上必须区分清楚，
    搞混了原型就没有意义了。
11. **预案切换用顶部常驻条，不用弹窗** —— 弹窗会打断正在进行的说话动作。
12. **路由不可变**：未配对 → 永远设备页；已配对 → 直接麦克风页。
13. **手动刷新扫描**，不持续轮询（省电）。
14. **已配对设备点一下直连**，不弹配对请求；只有未配对设备才走配对流程。
15. **电脑端停止收音时，手机端开始收音要震动 + 提示**
    「电脑端没有在收音，声音传不过去」。震动用 `navigator.vibrate`（iOS 没有这个 API，必须做保护），
    视觉提示是主要反馈渠道。提示条不能打断说话动作（`pointer-events-none`，不参与文档流）。
16. **`Collapse` 的 `className` 挂内层**，挂外层会留下 padding 空隙。
17. **不要用 `key` 当自定义 prop 传给子组件** —— 它是 React 保留属性，不会出现在 `props` 里，
    还会触发组件卸载重建。快捷键主键叫 `mainKey`。
18. **手机端所有弹层用同一套交互**：从下往上滑出 + 半透明遮罩 + 点空白退出（`DESIGN.md` §7.3）。
19. **配对码旁是「刷新」不是「复制」**；刷新后旧码立刻失效。

## 7. 动效与设计红线（最容易违反的部分）

```tsx
// ✅ 正确
import { fadeFast, springSmooth } from '@/lib/motion'
<motion.div initial={{ opacity: 0 }} animate={{ opacity: 1 }} transition={fadeFast} />

// ❌ 错误：手写 spring 参数
<motion.div transition={{ type: 'spring', stiffness: 300 }} />

// ❌ 错误：ease-in-out（DESIGN 明令禁止）
<motion.div transition={{ duration: 0.3, ease: 'easeInOut' }} />

// ❌ 错误：用 framer-motion 的 layout 做高度动画（靠 scale 校正，会把字压扁）
<motion.div layout />

// ❌ 错误：慢 spring 驱动 opacity（尾巴 600ms+，内容「半透明飘进来」）
<motion.div transition={springSmooth} animate={{ opacity: 1 }} />
```

两条铁律：
1. **高度变化用 `Collapse`**，不要用 `layout`；下方内容靠文档流跟随，兄弟节点不要再加 `layout`；
   列表重排用 `layout="position"`。
2. **透明度只用 `fadeFast`**（700/45，~150ms 收敛）。

## 9. 环境与坑（已经踩过的，别再踩一遍）

| 坑 | 说明 |
|---|---|
| **Node 必须 24** | Node 20 自带的 npm 10.8.2 装依赖会撞 arborist `edgesOut` bug。用 `nvm use 24` |
| **EasyUI 拉取** | GitHub API 会限流。已经装好了不用重拉；要拉走 `easyui.site/registry.json` + raw.githubusercontent |
| **EasyUI 的 `motion-tokens.ts`** | 它自己的 token（200/28、380/30、170/26）**不等于** `DESIGN.md`，也不等于 easyui.site 文档页的旧值。AirMic 自己的 UI 一律用 `@/lib/motion`，两套并存不冲突 |
| **lucide-react v1.61 缺图标** | 没有 `Screenshot`/`App`/`Unlock`/`Home`/`Music`/`Grid`/`LayoutApp`。用 `Camera`/`AppWindow`/`LockKeyhole`/`House`/`LayoutGrid`。`Image` 与 DOM 全局冲突，要 `import { Image as ImageIcon }` |
| **Tailwind v4** | `baseUrl` 已废弃（TS 6 报 TS5101），已从 `tsconfig.app.json` 删除；`paths` 用相对 tsconfig 目录的写法 |
| **framer-motion `layout`** | 尺寸补间用 scale 校正 → 中间文字被压扁 |
| **`AnimatePresence` 退出** | 会沿用同一份 transition。`repeat: Infinity` 的元素不能放进去（退出动画永远跑不完） |
| **React 的 `key` 保留属性** | 见硬约束 17 |
| **`aria-hidden` 的子树** | 里面的按钮会被剔出无障碍树，Playwright `getByRole` 也找不到。`PhoneOverlay` 的 portal 容器**不要加 `aria-hidden`** |
