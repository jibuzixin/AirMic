# AirMic 0.6.3

修复 0.6.2 里「自动重连还是连不上，点重试没反应，只能换设备重选」的问题。

## 原因

自动重连和手动「换设备」走的其实不是同一条路：

- 手动换设备：**重新扫描 mDNS** → 拿到电脑**当前**的地址 → 点一下连接。这条一直能用。
- 自动重连（0.6.2）：先试**上次保存的地址**，连接时还带着 **JS 里保存的 token**。

熄屏 / DHCP 续租后 IP 可能已经变了；或者 JS token 与原生 TokenStore 里的版本不一致。结果就是自动连接一直失败，而重试按钮也只是重复同一个旧地址，看起来像「没反应」。只有「换设备」重新扫一次才能真正连上。

## 修复

- **自动重连改成和手动换设备完全一致**：扫描 `_airmic._tcp` → 按电脑 id / 名字 / 已配对设备找到它 → 用扫描到的新地址连接。
- **不再带 JS token**：连接时交给原生 `TokenStore` 里配对时保存的那份 token，和手动连接一致。
- **重试按钮真的会扫描**：点「连接不上，点此重试」会显示「正在扫描电脑…」，扫描完直接用新地址连接；自动循环每一轮也会重新扫描。
- 扫描候选顺序：已保存的电脑 id → 电脑名字 → 手机本地有 token 的设备 → 如果局域网里只有一台电脑就用它。即使旧数据里没有地址，也能重新找回来。
- 增加 4 秒卡死保护：上一次连接调用如果一直不返回，不会把后续重试永久挡住。
- 移除了「只有 token 没有地址就回设备页」的逻辑；现在会先扫描尝试连接。
- 后台不扫描 / 不重连，回到前台再扫描；熄屏保活仍然交给前台服务，省电。

## 电脑端需要改吗

**不需要额外修改。** 0.6.2 的电脑端已经提供了 `welcome.features = ["ping"]` 和 ping/pong 响应，手机端的连接健康检查可以直接用。

0.6.3 也重新打包了 macOS 端（版本号对齐，功能与 0.6.2 相同）；你可以只更新 APK，也可以两端一起更新。

## 保留的 0.6.2 修复

- 回到 App 时连接还在就直接继续用，不再强制断开。
- 断连时点麦克风只提示并触发重连，不会启动采集、不会闪退。
- 采集线程防重入，采集失败自动回滚待机。

## 下载

| 平台 | 文件 | 说明 |
|---|---|---|
| macOS 13+ | `AirMic-0.6.3-macOS.zip` | 解压后把 `AirMic.app` 拖进「应用程序」 |
| Android 6.0+ | `AirMic-v0.6.3-debug.apk` | Debug 签名，直接安装 |

**macOS 首次打开**：右键 → 打开；或执行 `xattr -dr com.apple.quarantine /Applications/AirMic.app`。
然后授予「辅助功能」权限，并安装 [BlackHole 2ch](https://existential.audio/blackhole/)。

**Android**：允许安装未知来源应用，授予麦克风和附近设备权限，手机和电脑连同一个 Wi-Fi。

## 使用要求

- macOS 13 或更高版本；Android 6.0 或更高版本。
- 电脑需安装 BlackHole 2ch，其他软件把麦克风选为 BlackHole 2ch。
- 两端在同一局域网；访客 Wi-Fi / AP 隔离会导致扫描不到。
- 快捷键和文本粘贴需要 macOS「辅助功能」权限。
- 保活依赖 Android 前台服务，通知栏会有一条常驻提示。部分品牌（三星、vivo、小米等）的电池策略仍可能杀后台；如遇到断连，请把 AirMic 的电池设置改成「不受限制」。

## 已知限制

- Android APK 使用 Debug 签名，未上架应用商店。
- macOS 应用使用项目自签名证书，首次启动会有 Gatekeeper 提示。
- 目前只支持局域网，不支持跨网络 / NAT 穿透。
- iOS 客户端尚未开发。
