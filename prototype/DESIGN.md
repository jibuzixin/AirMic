# AirMic 设计契约

> 本文是 AirMic 的前端实现契约。**任何 AI 或人类在写 UI 代码前必须先读这份文件。**
> 违反本文的输出视为 bug，不是风格偏好。

---

## 1. 产品心智

AirMic = **把手机变成电脑的麦克风和遥控器**。

- 电脑端 = 服务端，只是一个**状态栏图标**（不占 Dock、不抢焦点）
- 手机端 = 客户端，是**真正的控制面板**，用户大部分时间在这里

**核心场景**：用户坐在电脑前，手边是手机。想说话 → 拿起手机按住 → 说话 → 松开。想让电脑执行某个操作 → 点手机上的磁贴。

因此：**手机端的操作必须是单手可达、零思考成本**。电脑端只是"确认"和"配置"的地方。

---

## 2. 视觉主题

**深色 + 单一强调色**。

界面质感对标 macOS 菜单栏面板和 iOS 控制中心：深色底、极少的分隔线、靠留白和字重建立层级，而不是靠边框和阴影。

**关键词**：克制、精确、物理。

**不做**：彩色渐变背景、发光描边、圆角大卡片堆叠、多彩图标、emoji。

---

## 3. 颜色

### 3.1 表面层级（从底到上）

| Token | 值 | 用途 |
|---|---|---|
| `surface-0` | `#0B0B0D` | 页面底色 |
| `surface-1` | `#141417` | 面板底、卡片底 |
| `surface-2` | `#1C1C20` | 输入框、悬浮层 |
| `surface-3` | `#26262B` | 按下态、选中态 |
| `border-subtle` | `#2A2A30` | 常规分隔线（1px） |
| `border-strong` | `#3A3A42` | 聚焦态边框、强调描边 |

**禁止纯黑 `#000000`**。最深是 `surface-0` 的 `#0B0B0D`。

### 3.2 文字层级（只有三级 + faint）

| Token | 值 | 用途 |
|---|---|---|
| `text-primary` | `#F2F2F4` | 标题、关键数值 |
| `text-secondary` | `#A0A0AA` | 正文、说明 |
| `text-tertiary` | `#6E6E78` | 辅助信息、时间戳 |
| `text-faint` | `#4A4A52` | 占位符、禁用 |

**层级靠字重和颜色差建立，不靠字号堆叠。**

### 3.3 强调色与语义色

| Token | 值 | 语义 |
|---|---|---|
| `amber-accent` | `#FFB020` | **唯一强调色**。主操作、聚焦环、电平高亮 |
| `connected` | `#35C98A` | 设备已连接 / 收音中（麦克风开启） |
| `recording` | `#FF5A5A` | 收音活跃状态、危险操作、删除 |

**规则**：
- 琥珀色是**稀缺资源**。一个视图里最多一处主操作使用它。
- **绿色 = 连接成功或麦克风开启**，红色 = 正在收音/危险。两者不混用。
- 语义色**只做状态指示**，不做装饰。

---

## 4. 字体

- **Sans**：`Inter` → `-apple-system` → `PingFang SC`（中文回退）
- **Mono**：`SF Mono` → `JetBrains Mono` — 用于**所有数值**（码率、延迟、电平、配对码）

**规则**：
- 所有数字、时长、频率、码率**必须**用 `font-variant-numeric: tabular-nums` + 等宽字体，避免跳动。
- 配对码用等宽，字符间距加宽（`letter-spacing: 0.2em`）。
- 层级靠字重：600（标题）/ 500（正文强调）/ 400（正文）/ 300（辅助）。**不要用 700+**。

---

## 5. 间距与圆角

- **间距刻度**：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40`
- **面板内边距**：16px（手机端）/ 12px（电脑端面板，更紧凑）
- **圆角**：
  - 大按钮 / 卡片：`24px`（麦克风主按钮用 `28px`）
  - 磁贴 / 控件：`12px`
  - 小徽章 / 药丸：`999px`
  - 输入框：`10px`

**不要**用 16px 以上圆角的小控件，也不要用 12px 以下圆角的大面。

---

## 6. 动效（这一节是 AirMic 的灵魂）

### 6.1 物理感优先

**所有过渡用 spring，不用 `ease-in-out`。** 线性缓动是"廉价感"的主要来源。

**动效 token 全部集中在 `src/lib/motion.ts`**，不要在组件里手写 stiffness / damping：

| Token | 参数 | 用途 |
|---|---|---|
| `springSmooth` | stiffness 300, damping 30 | 通用、面板展开 |
| `springSnappy` | stiffness 400, damping 25 | 按钮点击、磁贴按下 |
| `springBouncy` | stiffness 500, damping 15 | 麦克风按钮按下回弹 |
| `springGentle` | stiffness 180, damping 24 | 大范围位移、抽屉滑入 |
| `fadeFast` | stiffness 700, damping 45 | **透明度专用**（见 §6.3） |
| `layoutSpring` | stiffness 420, damping 38 | 高度 / 折叠（见 §6.3） |

### 6.2 时长

- 微交互（按下、hover）：**≤ 200ms**
- 元素进出：200–320ms
- 大范围形变：320–480ms
- **任何超过 500ms 的动画都是错的**

### 6.3 只动 transform 和 opacity

**禁止**动画 `width` / `height` / `top` / `left` / `margin`。用 `transform: translate/scale` + `opacity`。

需要高度变化时用 `framer-motion` 的 `layout` 属性或 spring 驱动的 `scaleY`。

> **⚠️ 2026-10-24 修订 —— 高度动画的实际做法**
>
> 上面写的 `layout` 属性在实践中**会把内容压扁**：`layout` 的尺寸补间是用
> **scale** 做校正的，元素高度从 44 变成 240，它就把元素 scaleY(5.5) 再反向补偿，
> **中间的子元素跟着被压扁** —— 展开过程中能明显看到标题和文字是扁的、发虚的。
>
> AirMic 统一改用 **`src/components/Collapse.tsx`**：spring 驱动的真实高度补间
> （`height: 0 → 'auto'`）。
>   - 高度是真的在变，文字全程清晰，不变形
>   - 下方内容靠正常文档流跟着走，**不需要**给兄弟节点加 `layout`
>     （给兄弟节点加 layout 反而会让它们一起被缩放）
>   - 代价是每帧触发布局 —— 318px 菜单栏面板 / 390px 手机屏里只有几十行，开销可忽略
>
> 同理，**列表项重排**用 `layout="position"`（只补间位置，不做尺寸缩放），
> 不要用完整的 `layout`。
>
> **透明度另有一条硬规则**：不要用慢 spring 驱动 opacity。
> spring 驱动透明度时尾巴长达 600ms+，视觉上就是「内容半透明地飘进来」。
> 透明度一律用 `@/lib/motion` 里的 `fadeFast`（700/45，~150ms 收敛）。

### 6.4 麦克风按钮的特殊物理

麦克风主按钮是全 App 最重要的交互，必须有**按下压缩 + 释放回弹**：

- 按下：`scale 0.96`，阴影收紧
- 释放：`springBouncy` 回到 1，**有轻微过冲**（overshoot ≈ 1.02）
- 按住期间：环形电平表持续变化
- **长按与点击的判定阈值：220ms**。220ms 以内视为点击（切换常开/常关），超过视为按住通话。

**图标表达「当前状态」，不是「点了会发生什么」**：

| 状态 | 图标 | 底色 |
|---|---|---|
| 待机（没在收音） | `MicOff`（麦克风是关的） | `surface-2` |
| 常开收音 | `Mic`（麦克风开着） | 琥珀 |
| 瞬时说话 | `Mic`（麦克风开着） | 录音红 |

> 早先的写法是「待机显示 Mic、激活显示 MicOff」，也就是图标在说"点了会开/会关"。
> 那样用户得翻译一次才知道现在是开着还是关着。改成状态语义后，
> 图标本身就是当前状态，不用动效解释。

### 6.5 悬停不发声

**鼠标悬停不做任何声音反馈。** 静置时完全安静。

## 7. 布局规则

### 7.1 电脑端（菜单栏面板）

- **宽度 318px**（固定，不要自适应）
- 纵向结构严格顺序：
  1. 状态行（连接状态 + 设备名 + 前台应用名）
  2. 配对码（6 位数字，折叠时隐藏）
  3. 音频输出设备下拉
  4. 启动 / 停止 主按钮
  5. **折叠的「详细设置」**（统计：丢包/抖动/欠载/延迟 + 抖动缓冲 + 1kHz 测试音）
  6. 退出
- 统计信息**默认折叠**，只在用户排查时展开。常态不占空间。
- **只有主按钮用琥珀色**，其余全部中性。

### 7.2 手机端

**路由规则（不可变）**：
- 未配对 → **永远**进设备页
- 已配对 → 每次打开**直接**进麦克风页

**麦克风页完全不滚动**（一屏放下）：
```
┌─────────────────────────┐
│  状态条（设备名/连接）  │  ← 顶栏
├─────────────────────────┤
│                         │
│    环形电平表 300px     │  ← 中部
│      + 麦克风按钮       │
│                         │
├─────────────────────────┤
│  3×2 遥控磁贴           │  ← 底部
└─────────────────────────┘
```

- 设备页和设置页**可以**滚动
- 磁贴固定 3 列 × 2 行，**磁贴只对应电脑热键**（图标 + 名称 + 组合键，三行）
- 触控目标 ≥ 44px

### 7.3 弹层规范（手机端统一）

手机端**所有**弹层 —— 预案编辑抽屉、磁铁选择器、磁铁编辑器 —— 必须用同一套规则，
不能一个有动画一个没有、一个能点空白关闭一个不能：

| 规则 | 实现 |
|---|---|
| 从**下往上**滑出 | `initial={{ y: '100%' }}` → `animate={{ y: 0 }}`，`springSmooth` |
| 后面一层半透明遮罩 | `rgba(11, 11, 13, 0.55~0.7)`，`fadeFast` 淡入淡出 |
| **点空白处退出** | 遮罩 `onClick` 关闭，跟关闭按钮等价 |
| 顶部拖动条 + 右上角关闭按钮 | 三种关法并存 |

> 遮罩和抽屉都要能被 `AnimatePresence` 接管退场动画 ——
> 所以遮罩和抽屉都是 `motion.*`，而且放在同一个 `AnimatePresence` 下面。
> 只给内层加动画、外层是普通 `div` 的话，退出时会「啪」地一下消失。

### 7.4 磁贴的显示规则

手机端磁贴显示的是**电脑端快捷键**，所以：
- 磁贴三行结构固定：**图标 / 快捷键名称 / 组合键**
- 组合键用等宽字体（如 `⌘⇧V`）
- **磁铁没配任何键时磁贴显示为暗态**（第三行写「未设置」），
  点击提示去配置这个磁铁

磁铁 = 图标 + 名字 + 按键组合，是**全局**的：磁贴和麦克风按钮的按下/松开
共用同一批磁铁。磁贴区的键位可以随时换成另一个磁铁。

## 8. 预案系统（Preset）

这是 AirMic 的差异化功能，UI 上必须体现清楚。

**预案 = 一套完整的快捷键方案**，包含：
- 麦克风按钮的"按下"快捷键（可选）
- 麦克风按钮的"松开"快捷键（可选）
- 其他独立快捷键按钮的绑定（可多个）

**绑定规则**：
- 预案可绑定到一个**电脑端前台应用**（如"微信"→ 预案A，"终端"→ 预案B）
- 电脑端检测到前台应用变化 → **自动切换**到对应预案
- 若当前应用**没有绑定**任何预案 → 切换到**默认预案**
- 切换必须有**可见反馈**：手机端顶部显示"已切换到 XX 预案"

**UI 表达**：
- 预案切换是**顶部一条细的状态条**，不要用弹窗打断
- 预案列表页每项显示：名称、绑定应用图标、绑定快捷键数量
- 默认预案要有明确标识（如"默认"标签）

---

## 9. 状态覆盖

每个交互元素必须覆盖这些状态，**不允许只画默认态**：

`default` / `hover` / `focus-visible` / `active` / `disabled` / `loading` / `error`

**空状态**：不能只写"暂无数据"，要说明怎么产生数据（"还没有连上设备，刷新试试"）。

---

## 10. 禁止清单（AI Tell）

以下一律禁止，出现即为 bug：

- ❌ 紫蓝渐变背景
- ❌ 大面积发光 / 霓虹描边
- ❌ 三个并排的等高功能卡片
- ❌ 假数据指标（`99.99%` / `50%` / `18.5k`）——**没有真实数据就留空或写 `[--]`**
- ❌ emoji 作为图标
- ❌ 圆角胶囊按钮里塞 emoji
- ❌ 多余的副标题解释用户已经知道的事
- ❌ 阴影堆叠（一个视图里最多一层阴影）
- ❌ 线性 `ease-in-out` 动画
- ❌ 动画 `width/height/top/left`
- ❌ 纯黑 `#000000`
- ❌ Inter 之外的默认系统字体兜底做标题（正文可以）
- ❌ 「Welcome back!」这类 AI 味文案

---

## 11. 交互文案

- 用**主动语态**，说人话
- 同一流程里**动词保持一致**（都用"连接"或都用"配对"，不要混）
- 错误要说**发生了什么 + 怎么修**：
  - ❌ "配对失败"
  - ✅ "配对码已过期，重新在电脑上生成一个"
- 主操作动词具体：`连接` `配对` `开始收音` `停止收音` `保存预案`

---

## 12. 性能约束

AirMic 是常驻工具，**UI 不能拖垮系统**：

- 空闲 CPU < 0.3%
- 常驻内存 < 40MB
- 电平表动画**只在收音时**运行，收音停止必须完全停帧
- 页面隐藏时暂停所有动画（`visibilitychange`）
- 长列表用虚拟滚动或分页
