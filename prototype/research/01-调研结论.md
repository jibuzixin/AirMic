## 一、Figma MCP（已放弃，但结论存档）

### 1.1 结论

**Figma 确实有官方 MCP，能免装桌面版使用，但免费额度基本不可用。**

用户最终选择放弃 Figma。原话："figma太贵就算了，我本意也不是想用figma"。

### 1.2 两种 server

| | 远程 | 桌面 |
|---|---|---|
| 地址 | `https://mcp.figma.com/mcp` | `http://127.0.0.1:3845/mcp` |
| 需装桌面版 | **否** | 是（需 Dev/Full 席位） |
| 写画布 | 支持 | 不支持 |
| 传输 | Streamable HTTP + OAuth | 本地 HTTP |
| 工具数 | 35（18 读 / 11 写 / 6 Weave）+ 1 prompt | 同 |

### 1.3 真正的坑：配额

- Starter / View / Collab 席位：**每月 6–20 次读调用**（官方两处文档数字不一致：docs 写 20，mcp-server-guide 仓库写 6）
- Dev / Full 席位：Professional 200 次/天（15 次/分），Organization 200–600 次/天，Enterprise 600 次/天
- `add_code_connect_map` / `create_new_file` / `whoami` / `generate_figma_design` 不计配额
- **写画布需要 Full 席位**，且是 beta，"免费但明确会转按量收费"

一次真实设计稿的 design-to-code 会烧掉几十次调用 → 6–20 次/月只够看 demo。

### 1.4 客户端白名单

**只有 Figma MCP Catalog 里的客户端能连**，不是任何 MCP client 都行。目录里 24 个：
Claude / Claude Code / ChatGPT / Codex / Cursor / VS Code / GitHub Copilot CLI / Kiro / Grok / Google Antigravity / Xcode(beta) / Zed / Warp / Devin / Replit / Notion / Slack / Android Studio / Amazon Q 等。

⚠️ 不在 claude.ai 网页版对话里用，必须是 MCP 客户端。

### 1.5 关键设计洞见（对做 UI 协议的人有普遍价值）

> Figma MCP 的读工具**全部是 selection-scoped**（`get_design_context` / `get_variable_defs` / `get_metadata` / `get_screenshot` / `get_motion_context`）—— 它回答"这个 frame 里有什么"，但不回答"我们团队哪个按钮变体才对""18px 间距是刻意的还是漂移""这张表空/错/加载态长什么样"。

**这些是约定，不在任何单个 frame 里。** 设计师靠记忆补上，agent 只能瞎猜 —— 这正是一个产品看起来像四个产品拼起来的原因。

Figma 自己也知道这点，所以它 ship 了唯一一个 prompt：`create_design_system_rules`，专门用来生成"规则文件"。

**→ 这就是 `DESIGN.md` 存在的理由。** 我们的 DESIGN.md 承担 Figma MCP 补不了的那一层：Figma MCP 答"这屏长什么样"，DESIGN.md 答"我们的规则是什么"。

### 1.6 社区反馈（截至 2026，旧的"只读"抱怨已过时）

- 现在**能写画布了**（远程 server + Full 席位），2025 年的"官方 MCP 只读"结论已过期
- 但写画布产物质量一般，社区原话："像 junior junior designer"
- 大 selection 会慢/报错/返回不全 —— Figma 官方也这么说
- 桌面版不能写画布

### 1.7 替代品（如果以后要用）

- **Framelink / Figma-Context-MCP**（GLips）：~15.9k stars，MIT，**只读**，任意 Figma 账号（含免费）只要 Personal Access Token，输出描述性 JSON 且**保留组件嵌套**（官方版会 flatten），payload 小 ~50%
- **Penpot**：开源（MPL-2.0），**纯浏览器**不用装客户端，官方**双向** MCP（能读写画布），可 Docker 自架，设计文件是开放格式（SVG/CSS/JSON），原生 CSS Grid/Flex + W3C 设计 token
- **Paper**（open alpha）：code-native 画布，MCP 读写，HTML/CSS 即画布
- **Pen**：IDE 内的 agent 画布，MCP 原生

## 二、审美好一点的 skill

### 2.1 结论

**有，而且不止一种。关键判断：选一个主 skill，别装一堆。**

多个 taste skill 同时加载会互相矛盾（一个要 brutalism 一个要克制），
结果比不装更糟。这是多篇独立评测的一致结论。

### 2.2 awesome-design-skills（typeui.sh）—— 已实测验证

**这是最贴合"我想要简介现代动画丝滑"的选择。**

实测记录：
- 从 `https://typeui.sh/api/skills` 拿到注册表，**真实 67 套风格**
- 从 `https://cdn.jsdelivr.net/gh/bergside/awesome-design-skills@main/skills/index.json` 拿到索引（沙箱里 typeui.sh API 被 Vercel checkpoint 拦，jsDelivr 通）
- 实测拉了 `minimal` / `modern` / `sleek` / `stitch` / `impeccable` 的 SKILL.md，内容真实

**67 套完整清单**（实测，非转述）：
Agentic, Artistic, Bold, Brutalism, Cafe, Claymorphism, Clean, Colorful, Contemporary, Corporate, Cosmic, Creative, Dithered, Doodle, Dramatic, Editorial, Square, Pulse, Stitch, Expressive, Fantasy, Flat, Friendly, Futuristic, Glassmorphism, Gradient, Power, Material, Minimal, Modern, Mono, Neobrutalism, Neon, Neumorphism, Pacman, Paper, Perspective, Premium, Professional, Basic, Refined, Retro, Shadcn, Geometric, Skeumorphism, Sleek, Spacious, Storytelling, Tetris, Vibrant, Vintage, Levels, Bento, Lingo, Enterprise, Roku, Ant, Claude, Codex, Fiction, Immersive, Impeccable, Matrix, Riso, Sega, Sketch, Terracotta

**结构**：每套 = `SKILL.md`（给 AI 的可执行规则）+ `DESIGN.md`（给人看的意图）
**SKILL.md 实际章节**（实测 minimal 的内容）：
Brand / Style Foundations（字号梯度+字体+色值 token+间距刻度）/ Accessibility（WCAG 2.2 AA）/ Writing Tone / Rules: Do / Rules: Don't / Expected Behavior / Guideline Authoring Workflow

**安装**：`npx typeui.sh pull <slug>`（有 live preview 画廊：typeui.sh/design-skills）
**生成自己的**：`npx typeui.sh generate`
**注意**：CLI 是交互式的（要选输出格式 + provider），非交互环境要用 `printf '\n\n\n\n' |` 喂，或者直接用 jsDelivr 拉文件。

### 2.4 关键洞见

**「风格预设 skill」和「设计系统」是两件事。**
评测实测：在已有设计系统的 app 里加新页面，glassmorphism 预设会跟 app 打架；
而**能读你代码库的 coding agent 本身就能匹配**（它有你现有文件在 context 里）。
所以：

- 新项目（greenfield）→ 风格预设 skill 有用
- 已有设计系统 → 先让 agent 读你的代码 + DESIGN.md，比装预设 skill 有效

**这正是我们写 DESIGN.md 而不是装一堆 skill 的原因。**

### 2.5 反 AI slop 的共识禁令（多作者独立提出）

紫蓝渐变 / Inter 默认字体 / 三个并排等高卡片 / 假精度数据（99.99%）/ `SYSTEM // 2024` 这种标签 / emoji / 破折号 em-dash（taste-skill 认为是 LLM 第一视觉破绽）/ 居中 hero / 圆形 spinner。

这些我们已经写进 `DESIGN.md` §10。

## 三、跨端方案

### 3.1 结论

**原型用 Web（React），最终用 Tauri 2 包装。**

### 3.2 Tauri 2（2026 实测数据）

- v2 于 2024-10 稳定，当前 2.11.x（2026-07-01 发布 2.11.5）
- **一个代码库 → macOS / Windows / Linux / iOS / Android**
- 架构：Rust 内核 + 系统原生 WebView（macOS→WKWebView, Windows→WebView2, Linux→WebKitGTK, Android→系统 WebView）
- **包体 5–10MB vs Electron 120MB+**
- **内存 ~30MB vs Electron 150–300MB** ← 对 AirMic 的 <40MB 目标关键
- 安全模型：capabilities 三层（permissions → permission sets → capabilities），**默认拒绝**，比 v1 的 allowlist 严格
- 系统托盘：是它的强项 → **AirMic 菜单栏应用正合适**
- 已知短板：移动端比桌面端年轻、插件覆盖不全、构建比 Electron 慢（Rust 编译）、CSS 跨 WebView 有细微差异
- 生产案例：GitButler、Hoppscotch、Gitify、1Password 部分工具、Authme

### 3.3 Expo / React Native（备选）

- 一套代码 → iOS / Android / Web，Expo Go 扫码真机预览
- Expo 官方现在有 MCP + Skills + 云端模拟器（agent 可驱动模拟器并回传截图）
- **但**：macOS 桌面支持弱。如果"Mac 软件"指真正的 macOS 桌面应用，Expo 不合适
- 真实代码共享率 70–80%（导航/手势/native API 必然分叉）
- ⚠️ Rork 已放弃 RN 转 Swift+Kotlin 双原生，别选它
- Metro web 取代了旧 webpack web target（2025 弃用）

### 3.4 Flutter

渲染一致性最好，但 agent 设计 skill 生态弱，Web 预览重。AirMic 这种工具类不必要。

### 3.5 AirMic 的硬约束

**虚拟音频输入设备（BlackHole 那套）必须 Swift/ObjC/C++**，Web/Tauri/RN 都做不了。

最终架构：
```
UI 层    → React + Tailwind + Framer Motion → Tauri 2 → macOS .app / Android .apk
音频层  → Swift（AudioUnit / 虚拟设备驱动）
协议层  → 局域网自定义协议（少字段、单连接）
```

原型阶段只做 UI 层，这不影响任何决策。

## 四、其他查到的（可能有用）

- **Mobbin MCP**（2026-05 上线）：62.1 万真实 app 屏幕，远程 HTTP + OAuth，Pro €10/月。`get_screen_detail` 返回 base64 图片，多模态可直接看。
  有意思的数据：首月 31.7 万次查询，**top50 里没有一个说 "generate"** —— 大家拿它当"查"工具（查 login screen / onboarding / paywall 怎么设计），不是当生成器。
  → 适合做**交互模式参考**，尤其"某某界面别人怎么做的"
- **Stitch MCP**（Google Labs，免费）：单屏生成，输出 HTML+Tailwind，Gemini 3 Flash/3.1 Pro，OAuth token 约 1 小时过期，每日额度 UTC 午夜重置。适合快速出单屏
- **Mowgli MCP**：整款多屏 app 设计（先写 spec 再设计所有屏），16+ moodboard 风格，可导出 Figma / React+Tailwind
- **Expo MCP**：官方，100+ 生产 API
- **Playwright MCP / Chrome DevTools MCP**：验证环节用（截图对比、控制台/网络/性能检查）
