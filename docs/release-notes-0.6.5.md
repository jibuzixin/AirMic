# AirMic 0.6.5

修复「切到别的应用再回来，总是先显示重新连接」的问题。

## 原因

1 小时的设置是**后台闲置多久后主动断开**，不是「切后台就断」。

真正的问题是：连接建立后，保活前台服务没有在切后台时稳定地把进程留住；断线时又会立刻把服务停掉。于是切到别的应用后，进程被系统冻结，TCP 连接跟着死掉，回来只能重新连。熄屏但停留在当前应用时，进程还是前台，所以反而不会断——这和你看到的现象一致。

## 修复

- **连接一建立就启动保活前台服务**（TCP 连上就启动，不等 welcome），让进程从连接开始就处于前台服务保护下。
- **断线时不立刻停服务**：保留前台服务，让进程在后台继续存活，JS 可以自动重连；Wi-Fi 锁在 socket 已经断开后释放，避免无意义耗电。
- **闲置计时真正生效**：后台超过你设置的时间（默认 1 小时）才停止保活服务并断开；即使 socket 已经先断了，计时器也会停掉服务，不会一直挂着。
- **回前台补一次保活**：从后台回来时检查/更新前台服务，避免某些系统在后台启动服务被拒后一直没有保活。
- **健康检查放宽**：回前台 ping 的超时从 2 秒放宽到 3 秒，并且等待期间收到任何 pong 都算链路正常，减少刚唤醒时误判。
- 通知文案从「已连接 · 保持连接」改成中性的「后台保活中」，断线等待时也不会误导。
- 0.6.4 的 Wi-Fi 锁、电池优化入口、Mac App Nap 修复全部保留。

## 怎么验证

1. 两端更新到 0.6.5，连接一次。
2. 切到别的应用待 1–5 分钟，再切回来：应该直接是已连接，不再先显示「重新连接」。
3. 手机通知栏应该一直有「AirMic · 后台保活中」。如果没有，说明前台服务没有起来，请抓日志。
4. 锁屏几分钟再打开：应该也是直接可用。

如果还会重连，执行：

```bash
adb logcat -s AirMicPlugin AirMicControl AirMicService AirMicScan AndroidRuntime
```

关注：

- `连接保活服务已启动`
- `熄屏保活：持有 Wi-Fi 锁` / `释放 Wi-Fi 锁`
- `后台闲置计时`
- `连接断开`

这几行能区分是「服务没起来」「Wi-Fi 被系统断」还是「真的超过闲置时间」。

## 下载

| 平台 | 文件 | 说明 |
|---|---|---|
| macOS 13+ | `AirMic-0.6.5-macOS.zip` | 解压后把 `AirMic.app` 拖进「应用程序」 |
| Android 6.0+ | `AirMic-v0.6.5-debug.apk` | Debug 签名，直接安装 |

**安装后建议做一次**：设置 → 省电 →「允许后台运行（系统电池设置）」，把 AirMic 设为「不受限制」。三星 / vivo / 小米等系统的省电策略仍然可能杀前台服务。

## 已知限制

- Android APK 使用 Debug 签名，未上架应用商店。
- macOS 应用使用项目自签名证书，首次启动会有 Gatekeeper 提示。
- 目前只支持局域网，不支持跨网络 / NAT 穿透。
- iOS 客户端尚未开发。
- 熄屏保活期间持有 Wi-Fi 锁会增加一点耗电，闲置时间到达后自动释放。
